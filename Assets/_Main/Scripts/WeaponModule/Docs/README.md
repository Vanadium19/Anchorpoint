# WeaponModule

## Назначение

Модуль реализует оружие игрока: модель боезапаса, создание оружия, стрельбу, перезарядку, прицеливание, переключение и процедурную отдачу; анимации рук и оружия клиповые.

## Основные части

- `WeaponModel` хранит магазин и резерв патронов.
- `WeaponController` реализует `IWeapon` и связывает модель с представлением.
- `WeaponInventory` переключает оружие и публикует `CurrentWeaponChanged`.
- `WeaponFactory` создает контроллеры через Zenject.
- `AmmoReserveService` сохраняет боезапас между переключениями.
- `WeaponView` управляет аниматорами рук и оружия, процедурной отдачей и рассылает состояние оружия частям представления (звук, хват, патроны).
- `RecoilProcessor` и `SwayProcessor` рассчитывают процедурную отдачу и раскачивание.
- `WeaponAimPoseSolver` (`Core`) выводит позу прицеливания по установленному прицелу (см. «Модификации»).
- `AmmoPresenter` обновляет `AmmoView`.
- `WeaponStatComposer`, `WeaponStats`, `WeaponBuild` и `WeaponStatsProvider` собирают итоговые характеристики оружия с учетом модификаций (см. «Модификации»).

## Конфигурация

`WeaponConfig` содержит характеристики выстрела, магазина, перезарядки, прицеливания и процедурных эффектов. Значения урона, магазина и разброса — это базовые характеристики (`BaseStats`), на них накладываются модификации. Доступные оружию модификации в конфиге не перечисляются: они выводятся из гнезд на prefab оружия и из каталога модификаций (см. «Модификации»). `AimZeroDistance` — дистанция пристрелки при прицеливании (см. «Модификации»).

## Модификации

Итоговые характеристики оружия считает один конвейер: `WeaponConfig.BaseStats` → плоский список `WeaponStatModifier` всех установленных модификаций → `WeaponStatComposer` → `WeaponStats`. Результат хранит `WeaponBuild` (установленные `WeaponModificationConfig` и `Stats`). `WeaponController` читает урон, вместимость магазина и разброс только из `WeaponBuild.Stats`, а не из `WeaponConfig`.

Характеристики (`WeaponStat`): `Damage`, `MagazineCapacity`, `HipSpreadAngle`, `AimSpreadAngle`. Операции (`WeaponStatOperation`): `Add` и `Multiply`; значение `Multiply` — доля (`0.25` = +25%, `-0.6` = -60%).

Формула для каждой характеристики:

`value = (base + sum(Add)) * product(1 + Multiply)`, результат не меньше 0.

Порядок модификаторов на результат не влияет (композер сортирует их перед суммированием). `MagazineCapacity` в `WeaponStats` округляется и не меньше 1. Композиция чистая: `WeaponStatComposer`, `WeaponStats` и `WeaponBuild` не зависят от сцены и DI, их можно вызывать из EditMode-тестов и офлайн-инструментов.

- Совместимость выводится, а не перечисляется. Гнездо оружия и модификация ссылаются на один и тот же ассет `WeaponSocketType` (интерфейс гнезда: `Sight`, `Magazine`, `Barrel` в `Assets/_Main/Configs/Weapons/SocketTypes`). Модификация подходит оружию, если на prefab его `WeaponView` есть гнездо ее типа (`WeaponItemSo.HasSocket(type)`, источник правды — `WeaponView.ModificationView.Sockets`). Списков модификаций в данных оружия нет, записей «оружие x модификация» нет нигде.
- Каталог. `WeaponModificationCatalog` (один ассет `Assets/_Main/Configs/Weapons/WeaponModificationCatalog.asset`, ссылка на него в `WeaponInstaller.modificationCatalog` на `Player` в сценах `Camp` и `Game`) хранит все `WeaponModificationConfig` проекта. Вручную его не правят: Editor-постпроцессор `WeaponModificationCatalogPostprocessor` после импорта, перемещения или удаления любого `.asset` пересобирает список (порядок по `id`, затем по имени ассета) и сохраняет каталог, только если список изменился. Постпроцессор работает через `EditorApplication.delayCall`, поэтому срабатывает на следующем тике Editor (у несфокусированного окна тик может задержаться). Принудительно: `WeaponModificationCatalogPostprocessor.SynchronizeProject()`. Новый `WeaponModificationConfig` попадает в каталог сам, удаленный исчезает.
- Провайдер. `IWeaponStatsProvider.GetAvailableModifications(weaponItem)` возвращает записи каталога, тип гнезда которых есть у оружия (кэш по оружию, без аллокаций при повторе). `GetBuild(weaponItem, ids)` сопоставляет id с каталогом, пропускает неизвестные id (удаленный ассет) и id, чье гнездо оружию не подходит, и не возвращает `null` для оружия с конфигом. Без каталога провайдер падает сразу с понятным исключением. Экземпляр оружия хранит id установленных модификаций в `ItemTable.WeaponModificationMetadata` (`InventoryModule`); id в сохранениях не менялись.
- Гнезда и установка. На гнездо одного экземпляра оружия приходится не больше одной модификации, установка постоянна (снять нельзя). Правило проверяет установщик (`ArsenalModule`), а не композер и не провайдер. Название слота в Арсенале берется из `WeaponSocketType.NameKey`. Новый слот или несовместимый интерфейс — новый ассет `WeaponSocketType`, а не код.
- Применение. `IWeaponInventory.RefreshBuild(item)` пересобирает `WeaponBuild` и вызывает `WeaponController.ApplyBuild`, если контроллер для предмета уже создан; иначе сборка применяется при создании контроллера. `ApplyBuild` меняет вместимость магазина (`WeaponModel.SetMagazineCapacity` ограничивает текущие патроны, но не пополняет их) и обновляет представление.
- Цена и тексты хранятся в `WeaponModificationConfig` (`Costs`, `NameKey`, `DescriptionKey`, `Icon`); установкой за ресурсы занимается `ArsenalModule`.

### Представление модификаций

`WeaponView.ApplyBuild` рассылает сборку частям prefab (`WeaponViewPart.OnBuildChanged`). Внешний вид отвечает часть `WeaponModificationView` на prefab оружия. Модуль заменяет или переделывает штатную деталь, а не надевается поверх нее. Содержание на оружие растет как N + M: для оружия делается один набор (штатные детали, гнезда, переходник), для модификации один ассет, перемножения нет.

Что задается один раз на оружие (prefab `WeaponView`):

- Гнездо (`WeaponModificationSocket`): `type` (`WeaponSocketType`), `mount` (`Transform`, оси: +Z вдоль ствола, +Y вверх, мировой масштаб 1 или осознанный масштаб гнезда), `stockParts` (штатные детали, рендереры `MeshRenderer` или `SkinnedMeshRenderer`), `adapterPrefab` (необязательно: собственное железо оружия, соединяющее его с модулем), `eyeRelief` (метры от камеры до метки прицела при прицеливании, используется прицелами этого гнезда; подбирается не только по размеру окна, но и по отсечению ближней плоскостью), `clearanceAboveAxis` и `clearanceBelowAxis` (метры от оси `mount` вверх и вниз, в которых операции над деталями должны оставаться; 0 — без ограничения).
- Штатные детали — отдельные рендереры (меши из `WeaponMeshPartExtractor` или Part Splitter), остаток оружия — отдельный меш тела.
- Переходник (`adapterPrefab`): prefab без компонента `WeaponAttachment` с креплением и приподнятой мушкой данного оружия. Создается под `mount` один раз, пока в гнезде есть модуль-объект, и скрывается вместе с ним. Так гнездо остается стандартным интерфейсом, а особенности оружия остаются на оружии (`Attachments/AK74SightAdapter`, `RevolverSightAdapter`, `ShotgunSightAdapter`).
- Стандартная точка интерфейса — основание модуля (начало корня `WeaponAttachment`). Для прицела `mount` стоит в основании коллиматора. Если коллиматор на этом оружии нужен в другом масштабе (револьвер: 0.85), масштаб задается на `mount`, а переходник компенсируется обратным масштабом.
- `FrontSightPoint` на кончике штатной мушки (если прицел приносит свою мушку, то на ее кончике, `aimPoint` не двигается).

Что задается один раз на модификацию (`WeaponModificationConfig`):

- `socketType` — какому гнезду подходит; `attachmentPrefab` (необязательно) — prefab с `WeaponAttachment` на корне (`aimPoint`, `reticle`, `reticleWindowHalfSize` для прицела; начало корня — точка контакта с `mount`, +Z вдоль ствола, +Y вверх, масштаб 1:1 в метрах); `partOperation` (необязательно) — ассет операции над штатными деталями; `modifiers`, `costs`, ключи и иконка. Ни prefab, ни операции — модификация только меняет характеристики. Prefab и операция вместе допустимы.
- `WeaponModificationView.OnBuildChanged` для каждого гнезда находит установленную модификацию его типа: prefab создается под `mount` один раз на пару (гнездо, prefab) и дальше только включается и выключается, слой крепления ставится всей иерархии, штатные детали гнезда скрываются, пока модуль показан; операция подменяет меш каждой штатной детали на обработанную копию и возвращает исходный при снятии. `TryGetSight` отдает метку установленного прицела и `eyeRelief` его гнезда.

#### Операции над деталями

Операция — ассет, наследник `WeaponPartOperation` (один класс на ВИД операции, не на оружие и не на модификацию). Контракт: `Mesh Apply(in WeaponPartContext)`, чистая работа с данными меша без сцены. Контекст: исходный меш, матрица `MeshToMount` (из пространства меша в пространство `mount`; для `SkinnedMeshRenderer` через bind pose кости, под которой стоит `mount`, поэтому работает одинаково для скиннинговых и обычных деталей), `ClearanceAbove`, `ClearanceBelow`. Результат сохраняет число вершин, треугольники, подмеши, UV, веса костей и bind poses; нормали и границы пересчитываются, NaN не возникает.

- `RadialThickenOperation` (`Configs/Weapon Part Operations`): `radialScale` (множитель расстояния от оси Z гнезда), `minRadius` (вершины ближе к оси не двигаются, канал ствола остается каналом), `axialFalloff` (доля длины с каждого конца, где эффект нарастает; 0 — равномерно). Рост по Y ограничивается `clearanceAboveAxis`/`clearanceBelowAxis` гнезда: вершина с `|y|` больше зазора не масштабируется. Ограничение действует только по вертикали (`y`).
- `CurveExtendOperation`: `lengthScale` (длина детали ниже выхода как кратное исходной), `rigidEndFraction` (доля длины у дальнего конца, которая едет жестко). Соглашение для `mount`: начало на выходе детали (горловина магазина), -Y внутрь детали, +Z вперед; по вершинам ниже выхода автоматически подбирается дуга окружности, длина дуги между выходом и жестким концом растягивается, сечение сохраняется; прямая деталь вытягивается по прямой; выше выхода ничего не двигается.
- Результаты кэширует `WeaponPartMeshCache` по (исходный меш, операция, положение): статический кэш очищается при перезагрузке домена и при изменении ассета операции в Editor. Стоимость первого применения измеряется (на этом проекте порядка мс для ствола и десятков мс для изогнутого магазина АК), повтор почти бесплатен. Исходные меши деталей должны быть читаемыми (`isReadable`): на сгенерированных ассетах деталей включить чтение, FBX не трогать.
- Одна операция общая для всего оружия: `Operations/ReinforcedBarrel.asset` (толщина ствола) и `Operations/ExtendedMagazine.asset` (удлинение магазина). Если одно значение параметра не подходит оружию, подбираются зазоры гнезда (`clearance...`), а не отдельные ассеты операций.
- Новый вид операции (например, укорочение или смещение) — единственный случай нового C#: новый наследник `WeaponPartOperation`. Новая модификация и новое оружие кода не требуют.

Штатные детали по оружию:

- АК: прицел скрывает штатную прицельную планку (`AK74_StockRearSight`), магазин — `AK74_StockMagazine` (гнездо у горловины магазина под костью `mag_bone`, чтобы деталь и модуль ехали за рукой при перезарядке), ствол — `AK74_StockBarrel`. Штатная мушка остается и служит `FrontSightPoint`.
- Револьвер и дробовик: переходник прицела приносит приподнятую мушку (`FrontSight` в `RevolverSightAdapter`/`ShotgunSightAdapter`), а гнездо прицела скрывает штатную мушку (`StockFrontSight`); `FrontSightPoint` — кончик приподнятой мушки. Гнездо ствола оперирует над `StockBarrel`.
- Зазоры гнезда ствола подобраны по геометрии оружия: АК — выше оси 12 мм (газовая трубка); револьвер — выше 18.2 мм (верх рамки), ниже 35.2 мм (низ рамки и подствольный выступ); дробовик — выше 17.8 мм, ниже 14.5 мм (верх цевья остается свободным). Параметры `ReinforcedBarrel`: `radialScale` 1.45, `minRadius` 2.5 мм.

Инструменты Editor (`WeaponModule.Editor`): `Tools/Weapons/Part Splitter` (`WeaponPartSplitterWindow`, API `WeaponPartSplitter.CreateStockPart`) — выбор островов меша рендерера или бокса, создание читаемых мешей штатной детали и остатка, нового рендерера-соседа с теми же материалами, костями и слоем; на инспекторе `WeaponModificationView` кнопка Add Socket Mount создает крепление с компенсированным масштабом; `WeaponViewValidator` и `WeaponBuildSweeper` проверяют prefab оружия (используются матричным тестом).

#### Прицеливание

С прицелом поза прицеливания не хранится в данных: `WeaponView` выводит ее каждый кадр через `WeaponAimPoseSolver` из `AimPoint` установленного прицела и `WeaponModificationView.FrontSightPoint` (мушка; без мушки линия берется по `FirePoint.forward`). Условия решения: линия прицеливания (от `AimPoint` к мушке) параллельна оси камеры, `AimPoint` лежит на оси камеры на расстоянии `eyeRelief`. Крен берется минимальным поворотом от `WeaponConfig.AimRotation`, поэтому оружие не заваливается. Авторских чисел позы под оружие или прицел нет; `AimPosition`/`AimRotation` из конфига при прицеле служат только базой крена, а без прицела (или без камеры) используется поза из `WeaponConfig`.

Почему поза пересчитывается каждый кадр: `AimPoint` и мушка двигаются вместе с клипами (idle-анимация). Их позиции переводятся в систему покоя `recoilPivot` (он лежит под `aimPivot`), то есть берется анимированное положение без процедурной отдачи и раскачивания. Так idle-анимация компенсируется и метка остается на оси, а отдача и раскачивание, которые `recoilPivot` накладывает сверху, сохраняются и решателем не гасятся. Между позой от бедра и решенной позой оружие движется по прогрессу прицеливания.

Пристрелка: при прицеливании выстрел идет в точку на оси камеры на расстоянии `WeaponConfig.AimZeroDistance` (`WeaponView.GetShotRotation`: поворот от `FirePoint` к этой точке, подмешивается по прогрессу прицеливания, чтобы не было рывка при подъеме оружия). Это действует и с механическим прицелом; разброс `WeaponController` накладывает сверху.

Точка коллиматора: красная точка коллимирована, то есть находится на бесконечности и не привязана к корпусу прицела. `WeaponView.UpdateProcedural` после записи `recoilPivot` и поворота камеры вызывает `WeaponModificationView.UpdateReticle`, а тот `WeaponAttachment.UpdateReticle`: точка (`Reticle`, дочерний объект `AimPoint`) ставится туда, где луч от камеры вдоль оси прицеливания (от `AimPoint` к `FrontSightPoint`, без мушки - `AimPoint.forward`) пересекает плоскость окна прицела (`WeaponReticleProjector.TryProject`, математика в локальной системе `AimPoint`, плоскость окна z = 0). Если луч выходит за окно (`reticleWindowHalfSize`, локальные единицы `AimPoint`, поэтому масштаб прицела не влияет) или камера не за окном, точка скрывается, а не рисуется на раме; с бедра она тоже скрыта. `AimPoint` остается неподвижным центром окна и по-прежнему используется решателем позы. Окно коллиматора 19 x 12 мм (половины 0,0095 x 0,006), запас под радиус точки 1,3 мм и зазор 1 мм дает `reticleWindowHalfSize` = (0,0072; 0,0037). Пока прицеливание достигло 0,9 (`WeaponView` передает `isAimed` по `_aimProgress`), точка не скрывается: выход луча за окно из-за отдачи ограничивается краем окна (`WeaponReticleProjector.TryProjectClamped`/`ClampToWindow`), а скрытие за окном действует только вне прицеливания, поэтому с бедра точка скрыта.

Аниматоры рук и оружия: `WeaponView.Initialize` включает `AnimatorCullingMode.AlwaysAnimate`. С отсечением по умолчанию (`CullUpdateTransforms`) аниматор не обновляет кости, пока ни один рендерер не виден, а решатель позы и IK хвата читают именно эти кости. Если поза от бедра сразу после `Equip` целиком вне кадра (револьвер), оружие застывало в позе кобуры и появлялось только после прицеливания. Прогресс прицеливания шагает не быстрее `MaxAimDeltaTime` (1/30 с) за кадр, поэтому долгий кадр не дает скачка позы.

### Тесты

`Assets/_Main/Scripts/WeaponModule/Tests` — EditMode-сборка `WeaponModule.Tests`:

- `WeaponStatComposerTests`: формула, независимость от порядка, пол в 0, минимум магазина.
- `WeaponAimPoseSolverTests`: после `Solve` метка и мушка лежат на оси камеры, метка на `eyeRelief`; наклонные и смещенные входы, ненормализованная ось, прицел без мушки, противоположная линия, стабильность крена, случайные входы.
- `WeaponReticleProjectorTests`: точка на оси, смещенная камера, наклонная ось, пересечение вне окна, камера за плоскостью окна, ось не вперед.
- `WeaponMeshPartExtractorTests`: острова, каждый треугольник ровно в одной части, сохранение подмешей, атрибутов и скиннинга, выбор по боксу и предикату, ошибка при пустом или полном выборе.
- `WeaponPartOperationTests`: радиальное утолщение (масштаб, минимальный радиус, зазоры, затухание по длине, вершина на оси, неверный масштаб) и удлинение по кривой (дуга, жесткий конец, ничего выше выхода, прямая и наклонная деталь, зазор, отсутствие NaN) на чистых данных; `Apply` сохраняет топологию, UV, скиннинг и плоскую заливку; кэш создает меш один раз и пересоздает после сброса операции.
- `WeaponBuildMatrixTests` (матрица сборок, управляется данными, имен ассетов в нем нет): каталог совпадает с ассетами, id уникальны и не пусты, ключи названий и описаний есть в таблице локализации, цены положительны, иконка есть, тип гнезда каждой модификации есть хотя бы у одного оружия; для каждого оружия и совместимой модификации — гнездо с `mount`, у прицела `aimPoint` и `reticle`, операция выполняется над каждой штатной деталью (число вершин, нет NaN, внутри зазоров, меши читаемы), у оружия с гнездом прицела есть `frontSightPoint`; каждый prefab создается один раз, применяется каждая комбинация по одной модификации на гнездо, проверяется включение и выключение штатных деталей и модулей. В выводе теста: оружие, модификации, совместимые пары, размер пространства сборок и доля допустимых сборок (сейчас 3 оружия, 3 модификации, 7 пар, 16 сборок, 100%).

Запуск: Window → General → Test Runner → EditMode, либо `Unity.exe -projectPath . -batchmode -runTests -testPlatform EditMode -assemblyNames WeaponModule.Tests -logFile -`.

## Типы патронов

`WeaponConfig.AmmoType` (`Rifle`, `Pistol`, `Shotgun`) задает тип боезапаса оружия. Предметы патронов используют `AmmoEffectDataSo` с совпадающим типом: патроны попадают в текущее оружие этого типа, а если оно не в руках, то в экипированное в слотах. `IWeaponInventory.CanAcceptAmmo` и `TryAddReserveAmmo` проверяют и добавляют резерв.

## Режимы стрельбы

- `IsAutomatic` — автоматический огонь при удержании или одиночный по нажатию.
- `ProjectilesPerShot` — число снарядов за выстрел (дробовик). Дробовик стреляет prefab `Pellet` — уменьшенная пуля с коротким сужающимся трассером и уменьшенным эффектом попадания (`hitEffectScale`).
- `SpreadAngle` — угол разброса в градусах для каждого снаряда при стрельбе от бедра; `AimSpreadAngle` — то же при прицеливании. Контроллер берет значение по состоянию прицеливания из итоговых характеристик (`HipSpreadAngle`/`AimSpreadAngle`), поэтому модификации влияют на оба.
- `FireInputBuffer` — сколько секунд помнится нажатие спуска, сделанное во время перезарядки затвора (`FireRate`); выстрел происходит, как только оружие готово. Быстрые клики короче кадра учитываются через `IsFirePressed`.

## Режимы перезарядки

- `Magazine` — полная перезарядка магазина за `ReloadTime`.
- `SingleRound` — по одному патрону за `RoundReloadTime`; выстрел при непустом магазине прерывает перезарядку.

## Части представления

Механизмы оружия (хват рук, видимые патроны, движущиеся детали, эффекты) — компоненты-наследники `WeaponViewPart` на prefab оружия. `WeaponView` не знает о конкретных частях: он рассылает всем частям prefab (находит их сам при первой рассылке) изменения состояния оружия — `Initialize`, `OnTriggerHeld`, `OnFired`, `OnActionCycleStarted`, `OnReloadStarted`, `OnReloadStateChanged`, `OnRoundInserted`, `OnLoadedRoundsChanged`, `OnHolsterStateChanged`, `OnPaused`, `OnAnimationEvent`, `ResetVisuals`. Часть переопределяет только нужные обработчики. Текущие части: `WeaponGripView`, `ChamberRoundsView`, `WeaponAudioView`, `MuzzleFlashView` (вспышка выстрела: prefab из WarFX создается у `muzzle` на каждый выстрел и живет `flashLifetime`). `FirePoint` (точка вылета пуль и обычно якорь `muzzle`) ставится на срез ствола модели: на оси канала ствола, `+Z` вдоль ствола, жестко под костью `gun_root_bone`, поэтому она не зависит от позы и отдачи. Для револьвера это точка среза ствола; штатный и усиленный стволы имеют один срез, поэтому одна точка подходит обоим. Если `FirePoint` стоит не на срезе (дальше от камеры по стволу или вне оси), вспышка и пули вылетают из корпуса или сбоку, а вспышка при прицеливании смещена от мушки.

Единая схема для звуков, анимаций и эффектов: каждый момент оружия — это id события (`WeaponEventIds`). Состояния поднимает `WeaponView` (`Fired`, `ReloadStarted`, `EmptyReloadStarted`, `RoundInserted`), моменты внутри клипа — Animation Event `RaiseEvent` с произвольным id. На id реагируют части. Аниматорами управляет только `WeaponView`, звуки играет только `WeaponAudioView`, эффекты и механизмы — отдельные части. Подход один для всех оружий, различается только содержимое prefab (какие части и какие привязки звуков).

## Анимации механизмов

Все движения рук и оружия — обычные `AnimationClip` в аниматорах `arms` (руки) и `gun` (оружие). Базовые контроллеры `acarms`/`acgun` общие; у револьвера и дробовика свои `AnimatorOverrideController` в `Assets/_Main/Animations/Revolver` и `Assets/_Main/Animations/Shotgun`, которые подменяют клипы АК и плейсхолдеры (пустые клипы в `arms/` и `gun/`, например `RoundReloadArms`, `ActionCycleGun`).

- Перезарядка магазином — триггеры `Reload`/`EmptyReload` (`EmptyReload` при `UseEmptyReloadAnimation` и пустом магазине). У револьвера `EmptyReload` — вариант без выброса гильз.
- Перезарядка по патрону — bool `IsRoundReloading`: состояние `RoundReload` с зацикленным клипом длиной `RoundReloadTime` (один патрон за цикл), выход с blend 0.2 с.
- Ход механизма после выстрела — состояние `Cycle` в слое `Action` обоих аниматоров (`WeaponView.PlayActionCycle`): у дробовика помпа (у рук слой аддитивный), у револьвера поворот барабана на одну камору. Клип барабана в конце вызывает событие `CompleteActionCycle` (id `ActionCycleCompleted`), барабан возвращается в исходный поворот, а `ChamberRoundsView` заново показывает патроны.
- Спуск — слой `TriggerPress` по bool `TriggerHold` у рук и у оружия; `TriggerPress → TriggerOut` ждет конца клипа, поэтому короткий клик доигрывает нажатие.
- `ChamberRoundsView` (револьвер) показывает патроны в каморах: массив `rounds` упорядочен от каморы под стволом в сторону вращения, `casings` — гильзы тех же камор, их видимость копируется с патронов в начале перезарядки (`OnReloadStarted`). Во время перезарядки патрон каморы прячется в том же кадре, когда аниматор показывает его гильзу (меши совпадают, вместе они мерцают), новое количество показывается по событию клипа `LoadRounds` (id `RoundsLoaded`, момент, когда спидлоадер отдает патроны) или по окончании/отмене перезарядки. Id событий задаются в инспекторе (`roundsAdvancedEventId`, `roundsLoadedEventId`), поэтому компонент подходит и для других видимых патронов (верх магазина, трубчатый магазин).
- `WeaponAnimationEvents` на объекте `gun` принимает Animation Event клипов `RaiseEvent(eventId)` — единственный вид события клипа. `WeaponView` передает id всем частям (`WeaponViewPart.OnAnimationEvent`). Id `ActionCycleCompleted` (клип барабана в конце) и `RoundsLoaded` (спидлоадер отдал патроны) — константы `WeaponEventIds`; остальные id (`CylinderOpen`, `Pump` и т.д.) произвольные и связываются со звуками в prefab.

Клипы револьвера и дробовика запечены из прежней процедурной анимации (IK рук к оружию уже внутри клипов). Длина перезарядки подгоняется под конфиг скоростью состояний `Reload`/`EmptyReload`/`RoundReload` (параметр `ReloadSpeed` в `acarms`/`acgun`): `WeaponView.PlayReload` ставит `длина клипа / ReloadTime` (или `RoundReloadTime`). Клипы рук для расчета задаются в `WeaponView` (`reloadClip`, `emptyReloadClip`, `roundReloadClip`); клип оружия той же длины. Без клипа скорость 1. Поэтому при смене времени в конфиге клипы править не нужно, а клип АК (2.97 с) растягивается под `ReloadTime` = 2 с.

## Хват рук

Движения рук и оружия задают клипы, а положение кистей на оружии — процедурный слой `WeaponGripView` поверх аниматора (гибрид). Подход одинаковый для всех оружий.

- `WeaponGripConfig` (`Assets/_Main/Configs/Weapons/Grips`) хранит для каждой руки (`HandGripData`) точку хвата и поворот кисти относительно якоря на оружии, повороты 15 костей пальцев, а для правой руки — позу указательного при нажатом спуске. `IsReleasedDuringReload` отдает руку клипу на время перезарядки.
- `WeaponGripView` на корне prefab оружия в `LateUpdate` тянет руку к точке хвата (`TwoBoneArmSolver`, изгиб локтя берется из клипа) и ставит пальцы. `HandRig` — кости руки и якорь: у правой руки это модель оружия (`RevolverModel`, `ShotgunModel`) или `gun_root_bone` (AK), у левой — деталь, за которую держится рука (`Pump` у дробовика).
- Нажатие спуска указательным процедурное (`triggerPressDuration`/`triggerReleaseDuration`, короткий клик доводит нажатие до конца); слой `TriggerPress` аниматора рук для указательного перекрывается хватом, спуск оружия по-прежнему анимирует аниматор `gun`.
- `WeaponGripView` — часть представления (`WeaponViewPart`): реагирует на спуск, перезарядку, паузу и сброс.

Как поправить хват: в Play Mode выбрать оружие, в инспекторе `WeaponGripView` → Pose Editing → `Begin Pose Editing` (аниматоры рук и оружия замораживаются), поставить кисть и пальцы, нажать `Capture Right Hand Grip` / `Capture Left Hand Grip` (для нажатого спуска — `Capture Trigger Press Pose`), затем `End Pose Editing`. Поза пишется в ассет конфига и сохраняется после выхода из Play Mode. Для нового оружия: добавить `WeaponGripView`, `Assign Bones`, задать якоря и конфиг, снять позы.

- Руки в prefab оружия используют меш `Assets/_Main/Models/Arms/arms.asset` — копию меша из `arms2.fbx`, у которой сечение фаланг `_02`/`_03` уменьшено на 3%/6%, чтобы грани соседних фаланг не совпадали (z-fighting на прямых пальцах).

## Звук

Звуки оружия проигрываются через `IAudioSystem` из `AudioModule`; в prefab задаются только идентификаторы событий банка `Weapons` (`WeaponsBankAPI`), собственных `AudioSource` у оружия нет.

- `WeaponAudioView` — единственное место звуков оружия, на корне prefab. Массив `sounds` связывает id события (`WeaponEventIds` или id из клипа) со звуком банка (`AudioEventKey`, id проверяется списком банка). Выстрел (`Fired`) ограничен по голосам: минимальный интервал `fireAudioMinInterval`, не больше `fireAudioMaxVoices` одновременно, самый старый гасится за `fireAudioStealFadeOut`. Если для `EmptyReloadStarted` звука нет, при перезарядке пустого магазина играет `ReloadStarted`.
- Звук перезарядки и последний звук из клипа хранят `AudioEventHandle` и затухают за `mechanismAudioFadeOut`, когда перезарядка завершена, прервана или оружие сброшено.
- `Bullet`: звук попадания с ограничением частоты; у дроби эффект попадания показывает каждая дробина, а звук — только одна (`SetHitSoundEnabled`). Пуля игнорирует коллайдеры стрелка, поэтому точка вылета может находиться внутри капсулы игрока.

`AudioEventHandle.Dispose(fadeout)` в ядре AudioModule гасит событие по id, а не конкретный экземпляр; для отдельного голоса используйте `Stop(fadeout)`, а после затухания — `Dispose()`.

Банк `Weapons` должен быть в `initialBanks` `AudioSystem` на сцене, где есть оружие (сейчас `Camp` и `Game`).

## Расширение

Новое оружие обычно добавляется новым `WeaponConfig` и prefab `WeaponView`. Общий ввод остается в `PlayerModule`, а контракт снаряда задается в `ComponentsModule`.

Расширение анимаций без изменения существующих классов:

- Новый механизм (затвор, магазин, лазер, счетчик) — новый наследник `WeaponViewPart` на prefab оружия; `WeaponView` подхватит его сам (массив `parts` обновляется при сохранении prefab).
- Новый момент в клипе — Animation Event с функцией `RaiseEvent` и строковым id; часть сравнивает id в `OnAnimationEvent`. Id лучше выносить в сериализуемое поле части, как в `ChamberRoundsView`.
- Новые клипы — через `AnimatorOverrideController` поверх `acarms`/`acgun`, хват рук — через новый `WeaponGripConfig`.

## Как расширить

Модификации и характеристики расширяются данными и точечными правками, конвейер остается общим.

- Новая модификация (работает на всем совместимом оружии без правок оружия и без C#):
  1. Создать ассет `WeaponModificationConfig` (Configs → Weapon Modification) в `Assets/_Main/Configs/Weapons/Modifications`: стабильный `id` (после релиза не менять, он хранится в сохранениях), `socketType`, модификаторы, цена, ключи и иконка. Каталог пополнится сам.
  2. Если модуль добавляет предмет: prefab с `WeaponAttachment` на корне (начало в точке контакта, +Z вдоль ствола, +Y вверх, 1:1 в метрах; для прицела `aimPoint`, `reticle`, `reticleWindowHalfSize`) в поле `attachmentPrefab`.
  3. Если модуль меняет форму штатной детали: ассет операции существующего вида (Configs → Weapon Part Operations) в поле `partOperation`; параметры общие для всего оружия.
  4. Создать ключи локализации `nameKey`/`descriptionKey`. Матричный тест покроет новую модификацию на всем оружии сам.
- Новое оружие (все существующие совместимые модификации заработают сразу):
  1. Разделить меш оружия на штатные детали через `Tools/Weapons/Part Splitter` (или `WeaponMeshPartExtractor.FindIslands`/`Split`): остаток остается телом, выделенные детали — отдельными рендерерами с теми же материалами, костями и слоем; меши читаемые, лежат в `Assets/_Main/Models/Weapons/<Оружие>`.
  2. Создать крепления гнезд (`Transform`, +Z вдоль ствола, +Y вверх, мировой масштаб 1; кнопка Add Socket Mount) и `FrontSightPoint` на кончике мушки. Крепление магазина — под костью магазина, начало на выходе из горловины; крепление ствола — на оси канала.
  3. На `WeaponModificationView` добавить гнезда: `type` (существующий `WeaponSocketType`), `mount`, `stockParts`, при необходимости `adapterPrefab` (железо этого оружия под прицел), `eyeRelief` (прицел), зазоры по оси для ствола. Подобрать зазоры так, чтобы утолщенный ствол не входил в раму, цевье, трубку; проверить матричным тестом и визуально.
  4. Создать `WeaponItemSo` и `WeaponConfig`. Списков модификаций у оружия нет.
- Новый тип гнезда: создать ассет `WeaponSocketType` (Configs → Weapon Socket Type) с ключом названия и добавить гнездо этого типа на prefab оружия. Кода нет; правило «одна модификация на гнездо» проверяется по ассету типа в `ArsenalModule`.
- Новая характеристика: добавить значение в `WeaponStat`, базовое значение — в `WeaponStats` (конструктор, `Get`) и в `WeaponConfig.BaseStats`, учесть ее в `WeaponStatComposer.Compose`, читать в потребителе из `WeaponBuild.Stats`. Чтобы характеристика попала на экран Арсенала, добавить ее в `StatDefinitions` презентера.
- Новый источник модификаторов (перки, износ): дополнительные `WeaponStatModifier` в тот же плоский список, который получает композер (точка сбора — `WeaponBuild.Create`). Отдельного конвейера для них не нужно.
- Правило стакования одинаковых модулей меняется в одном месте — `WeaponStatComposer`.
- Анализ пространства сборок: оружие (`WeaponItemSo`) → гнезда его `WeaponView` → записи каталога того же `WeaponSocketType` → `Modifiers`, `Costs`. Все данные доступны без запуска игры, итоговые характеристики сборки считает `WeaponBuild`; число сборок и долю допустимых печатает `WeaponBuildMatrixTests`.
